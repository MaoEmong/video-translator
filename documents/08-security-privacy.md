# 08. 보안과 개인정보

## 인증과 권한

- 모든 영상과 작업은 사용자 소유권을 확인한다.
- 다른 사용자의 `video_id`, `job_id`, `artifact_id`를 추측해도 조회할 수 없어야 한다.
- 관리자 기능은 별도 권한으로 분리한다.
- 세션과 refresh token은 서버 정책에 맞는 보안 저장소를 사용한다.

## 파일 보안

- Object Storage bucket은 private으로 설정한다.
- 업로드와 다운로드는 만료되는 signed URL을 사용한다.
- 확장자만 믿지 않고 MIME 타입과 `ffprobe` 결과를 확인한다.
- 서버가 생성한 랜덤 storage key를 사용한다.
- 필요하면 악성 파일 검사 단계를 추가한다.
- 처리 완료 후 파생 오디오와 chunk를 자동 삭제할 수 있게 한다.

## Secret 관리

- OpenAI API 키는 Secret Manager 또는 서버 환경변수에만 보관한다.
- API 키를 프론트엔드, DB, URL, 일반 로그에 저장하지 않는다.
- 개발·스테이징·운영 키를 분리한다.
- 키 교체가 가능하도록 애플리케이션 재배포 절차를 준비한다.

## 개인정보와 보관 정책

- 원본 영상, 파생 오디오, Transcript, 자막의 보관 기간을 별도 설정한다.
- 삭제 요청 시 관련 artifact와 파생 파일을 함께 삭제한다.
- 민감한 영상의 외부 API 전송 사실과 보존 정책을 서비스 약관에 명시한다.
- raw prompt와 raw provider response는 기본적으로 저장하지 않는다.
- 로그에는 원문·번역문 전체를 남기지 않고 ID와 상태 중심으로 기록한다.

## 남용 방지

- 사용자별 파일 크기와 영상 길이 제한
- 사용자별 일일 작업량 제한
- API rate limit
- 작업당 비용 상한
- 비정상 반복 요청 차단

## 삭제 흐름

```text
사용자 삭제 요청
  → 삭제 예약
  → DB 레코드 soft delete
  → Object Storage 파일 삭제
  → 보존 기간 경과 후 DB hard delete
```
