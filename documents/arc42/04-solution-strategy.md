# 4. 해결 전략

## 핵심 전략

1. 브라우저는 API에 대용량 파일을 전달하지 않고 signed URL로 Storage에 직접 업로드한다.
2. API는 작업을 DB에 기록하고 Redis Queue에 메시지를 넣은 뒤 즉시 응답한다.
3. Worker는 작업을 단계별 메시지로 처리하고 각 단계의 상태를 DB에 남긴다.
4. OpenAI 호출은 Adapter로 격리해 모델, timeout, provider 오류, 응답 검증을 한 곳에서 관리한다.
5. STT 원문과 번역 버전을 분리해 한 원문을 여러 목표 언어에서 재사용한다.
6. 자막의 시간 정보는 STT 세그먼트를 기준으로 하고, 번역 LLM에는 시간을 생성시키지 않는다.
7. 자막 export는 DB의 현재 번역 세그먼트에서 재생성한다.

## 선택의 이유

이 구조는 짧은 데모에서도 실제 운영 시스템의 핵심 문제를 드러낸다. HTTP timeout, 외부 API
실패, 파일 크기, 결과 버전, 편집 후 재생성 같은 문제를 코드와 문서에서 설명할 수 있다.

구체적인 선택 기록은 [ADR 목록](../adr/README.md)에서 확인한다.
